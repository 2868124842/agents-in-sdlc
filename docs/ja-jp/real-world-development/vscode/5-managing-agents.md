GitHub Copilot をエージェント モードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat では、自分のコンピューター上でリアルタイムに行われる作業を確認できます。各ツールの呼び出しとファイル編集を追跡し、差分をインラインでレビューして、個別の変更を承認または取り消せます。エディターを離れずに、追加のプロンプトで会話を案内し、作業内容を調整または拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして承認します。
- セッション中にエージェントを案内し、ハイ コントラスト モードに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントが、ハイ コントラスト モードを実装しています。作業中にデザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザーのために、ライト モードも追加したいとのことです。新しい会話を最初から始めるのではなく、進行中のセッションを案内して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューでは、エージェントが行う各手順、調査するファイル、実行するコマンド、提案する編集を確認できます。ファイルの編集は差分と **Keep** / **Undo** 操作とともにチャットにインライン表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められるターミナル コマンドが表示されます。
3. エージェントがファイルを編集すると、差分がインライン表示されます。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** インジケーターを開いて、このセッションでエージェントが変更したファイル全体を確認することもできます。

> [!NOTE]
> ツールの呼び出しで (たとえばターミナル コマンドの実行時に) 許可が必要な場合、エージェントは一時停止して **Allow** プロンプトを表示します。問題ないコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードを実装し終わるまで待ちます。変更の概要が最終メッセージに表示されます。

## ライト モードを追加するようエージェントに依頼する

ハイ コントラスト モードができたので、同じ会話にライト モードの切り替えを追加します。現在のセッションを続けるため、エージェントは前の作業のコンテキストを保持しています。変更したコンポーネント、使ったスタイル設定の方法、設定した local storage のパターンなどが含まれます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前回の変更を調べ、ライト モードを追加する作業を提案します。
3. 新しい編集をそれぞれ確認し、ハイ コントラスト モードの場合と同様に **Keep** または **Undo** を選択します。
4. エージェントが意図しない方法で進める場合 (たとえば、好みと異なる方法で切り替え UI をリファクタリングしようとする場合) は、入力欄の横にある **Stop** ボタンで停止して、明確な追加メッセージを送信します。

> [!TIP]
> 進行中のセッションを案内すると、最初からやり直すより効率的です。追加プロンプトで変更を依頼 ("CSS を簡潔にしてください。セレクターを重複させず、CSS 変数を使ってください")、方針を修正 ("3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを加えてください")、範囲を拡張 ("両方の切り替えにキーボード ショートカットも追加してください") できます。

## 作業内容をレビューする

変更をコミットする前に、エージェントが編集した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントが指示したアクセシビリティ パターン、ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使い、進行中のセッションを監視して案内しました。各ファイル編集を確認し、変更を承認または取り消し、コンテキストを失わずに追加プロンプトで作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個別のファイル編集を承認または取り消しました。
- 追加プロンプトで進行中のセッションを案内しました。

[次のレッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このラボ全体でローカルのカスタム エージェントが作成した変更をレビューします。
