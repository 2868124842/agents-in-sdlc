我们先为项目添加了一项小功能，但更复杂的更改需要更完善的流程。GitHub Copilot app 支持组织现有的工作流程，帮助我们用正确的方法构建所需功能。从本课开始，您将通过几节课遵循典型的智能体驱动开发流程：先使用 issue 生成新功能，确认代码有效且功能行为符合预期，最终将更改成功合并到项目中。

> [!NOTE]
> 在后续功能工作流中，您将沿用同一个会话。通常，不同类型的文件会使用不同的会话或 PR，但这里会采用简化方式，以便专注于核心概念。

本课将：

- 从 GitHub issue 启动新的智能体会话。
- 在 **Plan** 模式中定义需求。
- 使用 **Autopilot** 模式实现新功能。
- 评审代码。
- 在浏览器画布中手动验证功能。

继续完成该功能时，您将更新仓库说明、自定义现有的 quality-checks 技能、添加 MCP 验证、创建 QA 代理并打开功能 PR。

## 场景

Tailspin Toys 的游戏目录不断增长，访客需要按类别和发行商筛选游戏。待办 issue 描述了功能，但多个类别如何组合等细节需要在编码前达成共识。您将使用 Plan 模式确定这些决定，然后授权 Autopilot 在明确范围内实现功能。

## 背景

将 AI 编码代理引入开发流程不会改变基本原则。事实上，这些原则反而更加重要。大多数开发人员遵循类似以下的流程：

1. 打开已提交的 issue，查看需要完成的工作详情。
2. 制定实现计划。
3. 编写并评审代码。
4. 运行测试以验证代码。
5. 手动验证新功能。
6. 创建拉取请求（PR）。
7. 代码通过评审且持续集成流程成功后，合并代码。

> [!NOTE]
> 具体流程会因团队和组织而异，但大多数流程都是以上主题的变体。

坚持这种标准方法，可以确保 AI 生成的代码满足既定要求，并经过与手写代码相同的审核。

## 会话模式

**会话模式**控制代理的自主程度。可以从提示字段下方的下拉菜单中设置模式，并随时更改：

- **Interactive**：您与代理协同工作。代理提出更改建议，并等待您的输入后再继续。
- **Plan**：代理先制定计划。您评审并批准计划后，代理才会执行。
- **Autopilot**：代理完全自主工作，包括编写代码、运行测试和迭代，无需等待输入。

先在 Plan 模式下评审计划，再使用 Autopilot 实现。

## 从 issue 启动会话

开始前，确认星级评分 PR 已合并，并且本地 `main` 已更新。

1. 在侧边栏的 **Sessions** 下，选择 Tailspin Toys 仓库文件夹，然后在仓库顶部导航中选择 **Issues**。打开 **Allow users to filter games by category and publisher**。这是已有的模板 issue，无需另行创建。
2. 选择 **New session**，并选择基于更新后的 `main` 创建 **new working tree**。

    ![GitHub Copilot app 的 issue 视图，箭头指向 New session 按钮](../../../_images/app-new-session-from-issue.png)

3. 确认 issue 已附加到会话，并在模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，请让代理运行 `node --version` 和 `npm --version`。如果这些命令在终端中可以运行，但在会话中不可用，请检查应用的 PATH 或版本管理器配置，然后完全退出并重新打开应用。重试失败的操作和检查；不要仅仅因为代理找不到 npm 就重新安装 npm。

## 规划筛选功能

规划可以让您在 Copilot 编写代码前评审方案。由于会话从 issue 启动，Copilot 已获得功能请求的上下文。发送：

```plaintext
实现此功能。
```

回答 Copilot 的问题，并对照 issue 中的验收标准检查计划。确认计划涵盖类别和发行商筛选、无障碍控件、数据访问更改和测试。讨论尚不明确的行为，例如多个类别如何组合，或没有游戏匹配时如何处理。

计划应使用项目现有工具执行 lint、单元测试、E2E 测试和类型检查。将范围限定为实现和测试筛选功能；完成质量工作流后再创建 PR。批准前，要求修改计划中需要调整的内容，并保留 issue URL 和商定的澄清内容，供后续验证使用。

## 明确批准 Autopilot

对计划满意后，选择 **Approve and implement this plan**，或当前版本中的等效选项。不要假设批准计划会自动切换模式；请确认当前模式指示器显示 **Autopilot**。

Copilot 会开始实现功能。您会看到它按既定计划逐步推进、生成代码并运行测试。

> [!NOTE]
> 批准后可能立即开始实现，因此请先评审计划。如果 Copilot 报告缺少依赖项或端口冲突，请先解决环境问题，再将检查视为已完成。只停止自己启动的服务器。

## 评审并验证实现

生成的代码与其他代码一样，需要在合并前评审。下面来检查代码并运行网站，确认一切正常。

1. 打开 **Changes**，检查筛选功能的实现和测试。
2. 将结果与 issue 及已批准的澄清内容进行比较，包括多个类别和发行商组合的情况。确认更改遵循现有仓库说明。
3. 查看 lint、单元测试、E2E 测试和类型检查的输出。跳过的检查不能算通过。
4. 接受实现前，解决失败项并重新运行受影响的检查。Playwright E2E 配置会构建并提供预览服务，也可能复用本地服务器；确保被测服务器属于当前工作树，而不是之前练习中的工作树。

## 体验新功能

代码看起来没问题，但能否正常运行？像之前一样启动应用，并在浏览器画布中打开网站。

1. 使用以下提示，让 Copilot 启动应用并在浏览器画布中打开页面：

    ```plaintext
    启动应用，并在浏览器画布中打开。
    ```

2. 稍等片刻，应用将启动，Copilot app 内会打开浏览器窗口。
3. 选择一个类别，确认结果与之匹配。清除筛选，再选择一个发行商，确认结果与该发行商匹配。
4. 同时使用类别和发行商筛选器，并将结果与 issue 和已批准的计划进行比较。如果支持多个类别，请验证商定的组合行为。
5. 尝试一个没有匹配游戏的筛选组合，并检查空状态。清除或重置筛选器，确认完整列表重新显示。
6. 完成后，使用以下提示，让 Copilot 停止为此会话启动的开发服务器并关闭浏览器画布：

    ```plaintext
    停止开发服务器并关闭浏览器画布。
    ```
