在代理模式下使用 GitHub Copilot 时，它会自主探索代码库、提出更改、编辑文件并运行命令。由于这些工作会实时在您的计算机上进行，VS Code 中的 Copilot Chat 会持续显示每次工具调用和文件编辑。您可以内联评审每项差异、接受或拒绝单项更改，还可以通过后续提示引导对话，以完善或扩展工作，整个过程无需离开编辑器。

本练习将：

- 实时监控无障碍代理的工作。
- 评审并接受建议的文件编辑。
- 在会话中引导代理，在高对比度模式之外添加浅色模式切换。

## 场景

您在[练习 4][previous-lesson]中使用的无障碍自定义代理正在实现高对比度模式。工作进行期间，设计团队提出了新要求：他们还希望为觉得默认主题太暗的用户添加浅色模式切换。无需从头开始新对话，您可以引导现有会话扩展工作。

## 监控 Copilot 的进度

Copilot Chat 视图会显示代理执行的每个步骤，包括它浏览的文件、运行的命令和提出的编辑。每项文件编辑都会在聊天中内联显示差异以及 **Keep** / **Undo** 控件。

1. 返回练习 4 中使用的 Copilot Chat 视图。
2. 代理工作时滚动聊天内容，查看每次工具调用。您会看到文件读取、文件编辑，以及需要您允许运行的终端命令。
3. 代理提出文件编辑时，差异会内联显示：
   - 选择 **Keep** 接受更改。
   - 选择 **Undo** 撤销更改，让代理重新尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看代理在此会话中修改的全部文件。

> [!NOTE]
> 如果工具调用需要权限（例如运行终端命令），代理会暂停并显示 **Allow** 提示。只批准您确认安全的命令。

5. 等待代理完成高对比度模式实现。完成后会显示总结所做更改的消息。

## 引导代理添加浅色模式

现在高对比度模式已经实现，可以在同一对话中继续添加浅色模式切换。继续使用同一聊天会话时，代理会保留之前工作的上下文，包括涉及的组件、样式方案和设置的本地存储模式。

1. 在 Copilot Chat 输入框中发送以下后续提示：

    ```plaintext
    做得不错！现在请在高对比度切换旁边添加浅色模式切换。浅色模式应沿用相同模式，通过本地存储保留设置，并且可以从 UI 的同一区域访问。用户应能独立启用高对比度模式和浅色模式。
    ```

2. 代理会从之前的工作继续，探索已经完成的更改并提出浅色模式方案。
3. 新编辑出现时，像评审高对比度模式一样逐项检查，并使用 **Keep** 或 **Undo** 处理每项差异。
4. 如果代理采用了不希望的方向（例如以您不喜欢的方式重构切换 UI），可以选择聊天输入框旁的 **Stop** 按钮停止工作，然后发送澄清提示。

> [!TIP]
> 引导正在运行的会话比从头开始更快。可以使用后续提示调整方向（“简化 CSS，改用 CSS 变量，不要重复选择器”）、纠正方案（“不要添加第三个切换项，将浅色模式集成到现有设置面板”），或扩展范围（“同时为两个切换项添加键盘快捷键”）。

## 评审更改文件集合

提交工作前，快速检查代理修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 评审完整的已更改文件列表。应能看到 Astro 组件、样式和相关测试等文件。
3. 打开几个更改过的文件并查看差异。确认自定义代理要求的无障碍模式已落实，包括 ARIA 属性、键盘导航、语义化 HTML，以及通过本地存储保留设置。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。下一课会发布这些更改。

## 总结和后续步骤

您使用 Copilot Chat 代理模式监控并引导正在运行的会话：实时评审每项文件编辑、接受或拒绝更改，并通过后续提示扩展工作，同时保留上下文。

本课中，您：

- 实时监控代理的工作。
- 接受或拒绝单项文件编辑。
- 使用后续提示引导正在运行的会话。

在[下一课][next-lesson]中，您将把无障碍功能作为拉取请求发布，并评审本实验中本地自定义代理完成的更改。
